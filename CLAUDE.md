# CLAUDE.md

Tonchi (ex-Lexly): a gamified learning app. Vanilla JS/HTML/CSS on the web (no framework, no bundler),
and a SwiftUI iOS/macOS app reading the same content JSON. Live at lexly.heyitsmejosh.com, App Store id6783501611.
Renamed from Lexly on 2026-10-04; the App Store listing name, the web host, bundle IDs
(`com.nulljosh.lingo`), the Pages project `lexly-heyitsmejosh` and the Kotlin package still use the old name on purpose.

## Where things are

- `index.html` landing, `app/index.html` the app (screens are toggled divs), `js/lingo-app.js` all app logic
- `css/lingo.css` styles, `css/neutral.css` colours (white surfaces, brand blue `#2e86de`, no red accent)
- `content/catalog.json` tabs and courses, `content/courses/*.json` one pack per course
- `ios/Sources/Shared/` SwiftUI shared by iOS and macOS; `ios/Sources/Resources/content` is a symlink to `content/`
- `supabase/functions/` Stripe checkout; Supabase project is the shared `spark` one

## Content rules

- Exercise types and their fields: `translation`/`mathChoice`/`cloze` use `choices`, `sentence` uses `words`,
  `listening` uses `audio`, `match` uses `pairs`, `math` is free entry. **Every type must render on web and iOS.**
  `node tools/validate-catalog.js` guards this; keep it in sync when adding a type.
- Written courses are 6 units x 2 lessons x 5 `mathChoice` exercises, each with a unit `tip` and an `explain` on every
  answer. The app renders choices in file order, so shuffle them in the data (the answer must not sit in one slot).
- Every new course gets a second-model fact-check before it ships. First drafts had real wrong answers every time.
- Language packs are generated by `scripts/build-language-course.mjs` (Tatoeba pairs). The generated ones are not
  reviewed: 26 are held off the catalog because their sentences have errors. Do not add them back unchecked.
- Never ship book content (`books` category): Apple rejected macOS 1.1.4 over it. `CatalogView.categoryOrder` is explicit; do not sort alphabetically.

## Conventions

- Data-driven JSON, framework-free, no build step. Web and iOS/macOS change together. No emojis, no em dashes.
- Web gates the catalog behind an account; iOS/macOS deliberately do not (App Review 5.1.1(v)). Do not unify them.
- Keep the `srs` card shape identical on both platforms; both write the `srs` column.

## Deploy and test

- Deploy with `./scripts/deploy.sh`. A plain `git push` deploys nothing. It publishes the working tree, so do not run it mid-edit.
- Tests: `node tools/validate-catalog.js`, `node tools/check-streak-freeze.js`, `node tools/check-lesson-completion-scoping.js`, `node scripts/check-lesson-gate.mjs`, `ios/Tests/ContentStoreTests.swift`.
- Version state goes stale: `asc versions list --app 6783501611` is the truth. See `roadmap.md` before touching a submission.
