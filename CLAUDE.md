# CLAUDE.md

Guidance for working in this repo.

## What this is

Lexly — a gamified learning app: 12 languages plus math, science, programming, skills, and
BC curriculum courses. Static vanilla JS/HTML/CSS on the web (no framework, no bundler, no
build step) and a native SwiftUI iOS/macOS app sharing the same content JSON.

Live at lexly.heyitsmejosh.com · App Store id6783501611.

## Architecture

- `index.html` — marketing landing page (public root)
- `app/index.html` — single-page app shell, all screens are toggled divs
- `js/lingo-app.js` — app state, Supabase auth, progress sync, SM-2 spaced repetition, all
  exercise renderers
- `js/games.js` — arcade side-games (chess, 2048, memory, minesweeper, snake), not language
  exercises
- `css/lingo.css` — all styles, light/dark via `data-theme` on `<html>`
- `content/catalog.json` — course catalog; `content/courses/*.json` — course packs
- `content/notes/*.json` — masterclass notes; `school/` — gated BC curriculum HTML
- `ios/Sources/Shared/` — SwiftUI views shared by iOS and macOS. `ios/Sources/Resources/content`
  is a **symlink** to `content/`, so content changes reach the app with no copy step

## Content

Exercise types, and the fields each renderer actually reads:

| type | fields |
|---|---|
| `translation`, `mathChoice`, `cloze` | `choices` |
| `sentence` | `words` (word bank) |
| `listening` | `audio` (spoken via TTS) |
| `match` | `pairs` — `[[prompt, answer], …]` |
| `math` | free entry |

**Every type must render on both web and iOS.** The Swift `Exercise` model silently dropped
`words` and `audio` for months: word-bank exercises rendered as an empty text field and
listening exercises had no audio at all, and nothing failed — the JSON was valid, it just
decoded to less. `tools/validate-catalog.js` now guards this; keep it in sync when adding a
type.

Language packs are generated by `scripts/build-language-course.mjs` from Tatoeba sentence
pairs (CC-BY 2.0 FR) ranked by OpenSubtitles word frequency. It **appends** generated units
(ids prefixed `t`) after the hand-authored ones and never touches them, so existing exercise
ids — and therefore committed SRS cards and `lessons_completed` keys — don't orphan. Safe to
re-run: `node scripts/build-language-course.mjs [lang …]`. Corpora cache in gitignored
`cache/`. Attribution is a CC-BY obligation, not a courtesy: `ATTRIBUTION.md`, the landing
footer, and an iOS Settings row.

## Backend

Supabase (shared `spark` project, URL + anon key in `js/lingo-app.js`). Tables
`lingo_profiles` and `lingo_progress`; the `srs` column is written by **both** platforms, so
SM-2 card shape must stay identical on each. Email/password plus Sign in with Apple and
Google. Stripe Pro subscription via `supabase/functions/`.

## Conventions

- Lesson content is data-driven via JSON, never hardcoded per-lesson HTML
- Keep it framework-free; don't introduce a build step or bundler unless explicitly asked
- Cross-platform: a change to mechanics or exercise types lands on web **and** iOS/macOS
- Accessibility: maintain the `aria-label`s and skip-link already in `index.html`
- No emojis in any UI

## Deploying

Run `./scripts/deploy.sh`. **A plain `git push` deploys nothing** — the Cloudflare Pages
project `lexly-heyitsmejosh` is not git-connected, and the site silently went 2 weeks stale
that way. The script stages only publishable paths into a temp dir first; don't deploy the
repo root, `ios/build*` blows past the Pages file-count limit. A second, unused `lexly` Pages
project exists — `lexly-heyitsmejosh` holds the custom domain.

## Testing

- `node tools/validate-catalog.js` — validates catalog structure, every referenced pack, and
  every exercise against the fields its renderers need on both platforms
- `node tools/check-streak-freeze.js`, `node tools/check-lesson-completion-scoping.js`,
  `node scripts/check-lesson-gate.mjs` — mechanic guards
- `ios/Tests/ContentStoreTests.swift` — decodes real content from disk (not via Bundle, to
  skip test-target resource wiring)
